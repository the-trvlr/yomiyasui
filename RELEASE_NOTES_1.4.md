# 読みやすい 1.4 — индекс словаря готов заранее

Версия 1.4 убирает самую дорогую часть загрузки словаря: индекс форм больше не
строится в браузере, а приходит готовым с CI.

## Что изменилось

### Индекс форм собирается на CI

Замеры показали, где уходило время после загрузки файла словаря: разбор JSON —
1,9 с, создание записей — 1,1 с, а построение индекса форм — **5,6 с** из 10.
Именно индекс оказался главным виновником: для 218 898 записей браузер
нормализовал ~500 тыс. форм (NFKC + приведение регистра) и наполнял два `Map`.

Теперь `scripts/build-dictionary.mjs` пишет ещё два файла:

- `forms-<ver>.json` — отсортированный индекс «нормализованная форма → записи»,
  13 МБ (3,5 МБ gzip);
- `forms-core-<ver>.json` — то же для «ядра» частых слов, 1,1 МБ (0,3 МБ gzip).

Браузер больше не нормализует формы: он загружает отсортированный массив и
ищет по нему бинарным поиском. Заодно исчезли `formIndex` и `prefixIndex` —
два `Map` на полмиллиона ключей.

### Поиск

Точное совпадение и поиск по префиксу (две первые буквы запроса) теперь идут по
отсортированному массиву. Поведение не изменилось: те же запросы возвращают те
же результаты.

## Замеры

Один браузер, локальная раздача, без замедления CPU:

| Метрика | 1.3 | 1.4 |
|---|---|---|
| Полная загрузка словаря | 9 054 мс | **4 075 мс** |
| «Ядро» частых слов готово | — | 898 мс |
| Построение индекса | 5 598 мс | **872 мс** (загрузка готового) |
| JS heap | 319 МБ | 265 МБ |
| 「静か」 | 4 результата, первым「静か」 | так же |
| 「ночь」 | 35 результатов, первым「暮夜」 | так же |

Повторить: `npm run dev`, затем
`node scripts/measure.mjs --url http://127.0.0.1:8000/site/`.

## Измеримость

В приложении появились `performance.mark()` на этапах словаря
(`dict:full:fetched`, `parsed`, `ingested`, `forms`, `indexed`), а
`scripts/measure.mjs` читает их и печатает разбивку. Раньше замер опирался на
текст статуса, который живёт доли секунды и проскакивал между опросами.

## Что дальше

- **Индекс глоссов**: поиск по русскому переводу всё ещё перебирает все записи
  линейно — это следующая цель.
- **Шардирование** полного словаря вместо 34 МБ целиком.
- Предрассчитанный индекс добавляет 3,5 МБ к полной загрузке; после шардирования
  его тоже можно будет грузить по частям.
